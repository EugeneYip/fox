## 一、先講三個數字

這三個數字解釋了「為什麼看起來像模板」。

### 1　桌機上一半的畫面是空的，而詩只佔 16%

`main` 的寬度**固定 832px**，不管視窗多寬：

| 視窗 | main | 左右留白 | 留白佔比 | 詩塊（版框） | 詩塊佔視窗 |
|---|---|---|---|---|---|
| 1280px | 832px | 224 / 224 | 35% | 276 × 204 | 22% |
| 1440px | 832px | 304 / 304 | **42%** | 276 × 204 | 19% |
| 1680px | 832px | 424 / 424 | **50%** | 276 × 204 | **16%** |

螢幕越大，設計越縮成中間一條。而**這一頁的主角是那首詩**，
它在 1680px 的螢幕上只有 276px 寬 —— 比旁邊的注解欄（736px）小一半以上。

這不是「留白很克制」，是**留白沒有被使用**：左右兩條各 400 多 px 的地方
什麼都沒有，連一條線都沒有。線裝書的版框外面是有東西的（書耳、邊欄、魚尾）。

### 2　字級用得很扁 —— 六成的用量擠在最小的兩級

`tokens.css` 有一組完整的流體字階（`--t-xs` 到 `--t-display`，最大 5rem）。
實際用量：

| token | 上限 | 用了幾次 |
|---|---|---|
| `--t-display` | 5rem | 1 |
| `--t-2xl` | 3.5rem | **0** |
| `--t-xl` | 2.5rem | 4 |
| `--t-lg` | 1.75rem | 8 |
| `--t-md` | 1.25rem | 13 |
| `--t-sm` | 0.9375rem | **32** |
| `--t-xs` | 0.8125rem | **28** |

**60 次在最小的兩級，13 次在 lg 以上，中間整整一級（`--t-2xl`）一次都沒用。**
畫面上每一塊的視覺重量因此差不多 —— 注、白話、狐狸說、聽朗讀
四個區塊，除了位置不同，看起來一樣重。

順帶：`--r-lg` 0 次、`--c-moss-wash` 1 次、`--c-seal` 1 次。

### 3　預算：CSS 還有 3.1 KB，CSP 雜湊還有 5 個，JS 一行都沒有

| 預算 | 現在 | 上限 | 餘裕 |
|---|---|---|---|
| 全站 CSS（gzip） | 10.9 KB | 14.0 KB | **3.1 KB** |
| 最大單頁 HTML（gzip） | 10.9 KB | 14.0 KB | 3.1 KB |
| CSP 雜湊數（單頁） | 36 | 41 | **5** |
| 一般頁面內嵌 JS | 2.9 KB | 3.0 KB | **0.1 KB** |

意思是：

- **全部只能是 CSS。** 內嵌 JS 只剩 100 B。
- **新的 CSS 寫進 `global.css` 不花雜湊**（外部樣式表）；
  寫進**新元件**的 `<style>` 每一個讓 63 頁每頁 ＋1，最多 5 個。
  改**既有**元件的 `<style>` 不花。
- 有一個之前沒注意到的空間：CSP 裡有 **`style-src-attr 'unsafe-inline'`**，
  所以逐元素的 `style="…"` 屬性是允許的、**零雜湊**。
  這讓「每一列一個 `view-transition-name`」這種做法變得可行。

## 三、這個瀏覽器上實際能用什麼（實測，不是查文件）

用 `CSS.supports()` ＋ 真的量版面。**✅ 表示量到它真的有作用**，
不只是「解析得過」—— 這兩件事在 WebKit 上差很多，下面有四個例子。

### 可以用

| | 能拿來做什麼 |
|---|---|
| `writing-mode` 全套 | 直排（已用）、留白處的直排書口 |
| container queries ＋ `cqi` | 列表項目依**自己的容器**變版，不是依視窗 |
| `:has()`、`@scope`、subgrid | 條件式版面、不用加 class |
| anchor positioning ＋ `position-area` | 注解貼著被注的字浮出來（零 JS） |
| `@starting-style` ＋ `transition-behavior` | 進場動作，不需要 scroll timeline |
| `view-transition-class`、`view-transition-name` | 跨頁轉場分組（已用基本款） |
| `text-emphasis` | **著重號**（中文的強調，不是粗體） |
| `ruby-position`、`font-variant-east-asian` | 注音／異體字 |
| 相對色 `rgb(from …)`、`color-mix()`、`oklch()` | 從既有 token 算出新色，不必再開 token |
| `@property` | 可動畫的自訂屬性（漸層、角度） |
| `mask-image`、`mix-blend-mode`、`clip-path: shape()`、`offset-path` | 紙、墨、印的質感 |
| `timeline-scope` | 捲動動作跨越 DOM 層級 |
| `scrollbar-gutter`、`::target-text`、`field-sizing` | 細節 |

### 量過之後**不能用**的四個（重要，省下四次白工）

| 想用的 | 結果 |
|---|---|
| **`text-spacing-trim`**（標點擠壓） | **完全不支援。** 七個值、`text-spacing` 簡寫、`-webkit-` 前綴全部 `false`；實測「銀床」），也 這串寬度 364.59px，加什麼都不變。連 OpenType 的 `halt`／`palt` 也不動。MDN 上有這個屬性，**Safari 沒有** |
| **`hanging-punctuation`**（標點懸掛） | **解析得過，但沒有任何效果。** `none`／`allow-end`／`force-end`／`first allow-end last` 四種，行寬全部是 182／182／122，一模一樣 |
| **`text-box-trim` 的 CJK 值** | `ideographic` 與 `ideographic-ink` **都是 no-op**（高度 50→50）。唯一有效的是拉丁度量：`cap alphabetic` 50→28、`ex alphabetic` 50→18 —— 拿拉丁的 cap height 去切中文會切歪。**對這個站沒用** |
| **`text-autospace`** | 支援，但**不需要**（量到的數字見下面那一段）。**維持手動** |

`text-autospace` 那一格的實測（`--f-serif`，20px）：

```
用 Astro 建的站   text-autospace:normal        137.53px
用 Astro 建的站   text-autospace:no-autospace  137.53px   ← 完全一樣
用Astro建的站     text-autospace:normal        132.02px   ← 自動加出來的
用Astro建的站     text-autospace:no-autospace  127.02px
```

兩件事：Safari **不會**在手動空格之外再加一次（上面兩行完全相同）；
而它自動加的空隙比一個半形空格窄 5px，比較接近專業排版的四分之一字寬。
但改用自動的會違反 `check:copy` 的 `cjk-latin-space`，
而且不支援的瀏覽器會退回成完全沒有空格。

### 一個有用但有代價的

**`text-emphasis`（著重號）**：可用，寬度不變，但**行高 +9px**
（20px 字、行高 1.85 時 37px → 46px）。
所以段落裡只要有一行帶著重號，那一行就比別行高 9px，行距會不齊。
**適合標題、引句、獨立的短句；不適合塞在 `.prose` 的段落裡**，
除非同時把 `.prose` 的行高抬到吸收得掉。

## 四、提案（按「看得出來的差別 ÷ 代價」排序）

每一項都標了代價與風險。**沒有一項需要 JS。**

### A　讓寬螢幕真的用上寬度　✅ A1／A3 2026-09-11 做了（A2 還沒）

**問題**：第一節那張表。1680px 下 50% 是空的，詩佔 16%。

三個可以疊加的做法：

- **A1　詩頁改成「詩 ＋ 旁注」兩欄。** 注解移到詩的右邊，
  像線裝書的旁注。只在夠寬時啟用（container query），窄螢幕維持現在的上下排。
  這同時解決了「詩太小」與「四個區塊一樣重」兩件事 ——
  詩塊可以放大到目前的兩倍還有餘。
- **A2　留白處放一條直排的書口。** 版心的資訊（書名／卷次／篇名）
  在線裝書上就是印在版心的。`position: sticky` ＋ `writing-mode: vertical-rl`，
  捲動時跟著。這是**唯一一個會讓人一眼知道「這不是模板」的東西**，
  而且它用的正是現在完全空著的那 400px。
- **A3　版框跟著字級走。** 現在 276px 是寫死的觀感；改成
  依 `--poem-longest-line` 與字級算，寬螢幕上自然放大。

**代價**：CSS only。A1／A3 改 `PoemBlock.astro` 既有的 `<style>`（0 雜湊）；
A2 若要新元件就是 1 個雜湊（36→37，還有 4 個）。估 CSS ＋0.4～0.8 KB。
**風險**：直排的軸向是反的（`inline-size` 是高度）；
`.poem__line { white-space: nowrap }` 與 `vertical-keep-all` 兩條規則都要遵守 ——
這兩件今天有關卡在守，改完跑 `check:content` 就知道。

#### A3 做出來是這樣（跟 B 一起）

詩的字級改成從容器寬度反推，版框從佔視窗 22～54% 變成 30～57%，
十一首都沒有橫捲。細節寫在 B 那一節。

#### A1 做出來是這樣

注挪到詩的右邊 —— 線裝書的旁注。**要不要並排不寫斷點**，
讓 `flex-wrap` 自己決定：詩那一欄照內容寬（`flex: 0 0 auto`），
注那一欄最少 20rem（`flex: 1 1 20rem`）。

| 詩 | 詩欄 | 注欄 | 結果 |
|---|---|---|---|
| 四句（八首） | 380px | 324px | **並排** |
| 八句（兩首） | 716px | 736px | 疊起來 |
| 十句（〈琵琶行〉） | 728px | 736px | 疊起來 |

也就是「**留得下就並排，留不下就疊起來**」—— 而這件事跟視窗寬度無關，
跟這首詩多寬有關。斷點問不到這個。

注的欄變窄時，詞條與解釋改成上下排，用的是**容器查詢**：
並排時那一欄只有 324px，而視窗可能是 1680px。

兩次都踩到同一個坑，**兩次都是「特異性一樣，後面那條贏」**：

1. `@container` 那一段寫在 `.poem__annotation` 基本規則**前面**，
   量到詞條那一軌仍然是 152px、解釋只剩 156px（約十個字）。
   容器查詢**不加特異性**。
2. `.poem__aside` 寫在 `.poem__section` 前面，而元素兩個 class 都有 ——
   量到注的上緣比詩低 48px（`--s-7` 原封不動地生效了）。

代價：CSS 11.1 → 11.2 KB，HTML 沒變，CSP 雜湊沒動（36）。
228 格的 WebKit 掃描重跑：0／0／0。

**還沒做的**：A2（留白處那條直排的書口）。那是這一項裡效果最強的一半，
但要新元件（1 個雜湊）。

### B　把字級層級拉開　✅ 2026-09-11 做了

**問題**：第二節那張表。60 次擠在最小兩級，`--t-2xl` 0 次。

**做法**：詩頁的 h1 升到 `--t-2xl`；列表頁的項目標題升一級；
把「注／白話／狐狸說」那三個 13px 的分節標題**改用字重與顏色分層**，
而不是全部縮到最小。分節標記（魚尾）已經在了，標題不必再靠「小」來讓位。

**代價**：`global.css` 幾行，0 雜湊，CSS ＋0.1 KB。
**風險**：字級變了行長會變 —— 斷行要用上一輪那支 WebKit 探針重量一次
（228 格那套現成的）。對比度不受字級影響，`check:contrast` 的 PAIRS 不用動。

#### 做出來是這樣

改了三處，**預算一毫沒動**（CSS 仍然 10.9 KB、CSP 雜湊仍然 36）：

| | 之前 | 之後 |
|---|---|---|
| 列表的項目標題 `.entry__title` | 20px（跟頁面引言、跟頁首站名一樣大） | **28px** |
| 詩 `.poem__original` | 28px（比標題 40px 還小） | **29.7～40px，依句數而定** |
| 空影片框的「狐」浮水印 | 96px（**全頁最大的字**） | 40px（不高於詩） |

詩的字級改成**從容器寬度反推**，而不是寫死一個值：
一欄佔 `font-size × 2.1`，扣掉版框內距與詩節之間的 gap，
剩下的除以句數就是「剛好放得下」的字級，上限 `--t-xl`、下限 `--t-lg`。
11 首量過，**全部 0 橫捲**，版框從佔視窗 22～54% 變成 30～57%。

這一版改對了兩次才成立，兩次都是量出來的：

1. 第一版只是把 `--t-lg` 換成 `--t-xl`（28 → 40px）。
   截圖才看到〈琵琶行〉溢出 212px 要橫捲 —— 而直排**從右邊開始讀**，
   捲軸停在左邊，一進站第一句就被切掉一半。「放大」換來「讀不到開頭」不划算。
2. 第二版用 `100cqi` 反推，結果算出 40px（剛好是 clamp 上限，
   跟沒生效長得一樣）。實測 `100cqi` ＝ **900px** ＝ 視窗的高 ——
   容器單位跟的是**元素自己**的行向，直排要用 `cqw`。
   換成 `cqw` 之後〈琵琶行〉還溢出 52px，因為它有三節，
   `gap` 兩個 ＝ 64px 沒算進去。補上才歸零。

（`cqi`／`cqw` 那個坑已經寫進 CLAUDE.md 的「直排的軸向是反的」。）

### C　列表頁要看得到詩　✅ 2026-09-11 做了

**問題**：`/poems` 11 列一模一樣，沒有一個字是詩。

**做法**：每一列加一枚「**詩的形狀**」—— 依格律畫一組小方格，像一枚小印。
資料已經齊全，而且**不必新增欄位**：直接數 `poem.original` 就得到精確的格子數。
全部 11 首都解析乾淨：

| 形狀 | 哪幾首 |
|---|---|
| 4 行 × 5 字 | 靜夜思、登鸛雀樓 |
| 4 行 × 7 字 | 出塞、芙蓉樓送辛漸、九月九日憶山東兄弟、秋詞、山行、烏衣巷 |
| 8 行 × 5 字 | 月夜、月夜憶舍弟 |
| 10 行 × 7 字 | 琵琶行（節錄） |

一眼就分得出絕句／律詩／樂府、五言／七言 —— 是資訊，不是裝飾。
用 CSS grid 畫，零 JS，零圖片。

（另一個選項 C2：每一列帶首句直排，`:hover`／`:focus-within` 時顯現。
但那在觸控裝置上出不來，而且瀏覽器窗格量不到 hover ——
C1 比較穩，兩個也可以都做。）

**代價**：`EntryCard` 既有的 `<style>`（0 雜湊）＋ 每列一個 data 屬性。
HTML 每列約 ＋30 B（gzip 後更少，重複性高）。
**風險**：非詩詞的集合（文章、短札）沒有形狀，要確定它們不會留下空位。

#### 做出來是這樣

那一格畫在列的**右緣** —— 也就是第一節說的那塊沒被使用的留白。
十一列的形狀一路看下去，絕句、律詩、樂府一眼分得出來。

| | |
|---|---|
| 畫法 | 兩道 `repeating-linear-gradient`，**沒有任何子元素** |
| 為什麼 | 一首七言絕句是 4 × 7 ＝ 28 格，十一列就是 308 個元素，而 HTML 只剩 3.1 KB |
| 外框／格線 | `--c-rule-strong`／`--c-rule` —— 跟詩頁的版框（外粗內細）與界欄同一套說法 |
| 回饋 | `:hover` 與 `:focus-within` 時外框轉狐火色 |
| 窄螢幕 | 收起來（那裡每一格橫向空間都要省） |
| 無障礙 | `aria-hidden` —— 格律已經以文字在標籤裡（「五言絕句」），讀出來只會變噪音 |

代價：HTML 10.9 → 11.1 KB、CSS 10.9 → 11.1 KB（各 ＋0.2），**CSP 雜湊沒動**。

踩到一個坑，記在 CLAUDE.md 了：第一版用 grid ＋ `.entry > * { grid-column: 1 }`，
結果標籤跑到第二軌跟描述並排、形狀跑到標題上面。兩個原因疊在一起 ——
`TagList` 是**另一個元件、帶別的 cid**，`.entry[cid] > *[cid]` 配不到它；
而那條選擇器有兩個屬性，**特異性還高過 `.entry__shape[cid]`**。
包一層 `.entry__body` 兩個問題都沒有了。

### D　文章裡的引詩要跟散文長得不一樣

**問題**：〈把詩翻成白話的三個難處〉裡「兩個黃鸝鳴翠柳，一行白鷺上青天。」
跟旁邊的散文同一個樣子。這是詩詞站。

**做法**：`.prose` 裡的引詩用版框的輕量版（單線框 ＋ 界欄），
或者乾脆直排 —— 站上已經有這兩套語彙，不必發明新的。

**代價**：`global.css` 幾行，0 雜湊。
**風險**：要有辦法分辨「引詩」與「一般引言」。現在 markdown 裡是
`「…」` 夾在段落中，可能需要改寫成 `blockquote` —— 那是**內容的改動**，
要站主決定。

### E　著重號取代粗體　✅ 2026-09-11 做了

**做法**：`text-emphasis: filled dot` 用在引句與標題的強調，不用在段落內。
**代價**：兩三行 CSS。
**風險**：已量到 —— 行高 +9px，所以範圍要收窄。用 `currentColor` 就不會多出
新的前景×背景組合，`check:contrast` 的 PAIRS 不用加。

#### 做出來是這樣

比研究時預想的**更進一步**：不是「粗體之外再加點」，是**點取代粗體** ——
那才是中文的規矩（`font-weight: inherit` ＋ `text-emphasis: filled dot`）。
中文的明體加粗之後是一團更黑的字，看得出來「這裡不一樣」，
但看不出來「哪幾個字」。

在真的段落上重量一次（`.prose`，20px／行高 1.85）：

| | 行距 | 兩行的段落 |
|---|---|---|
| 沒有著重號 | 37px | 74px |
| `filled dot`（`under`） | **46px** | 92px |
| `filled sesame` | 44px | 88px |
| `over` | 47px | 94px |

**接受那 9px 的理由**：站上 `<strong>` 很稀疏（每篇「狐狸說」一到兩處），
受影響的是一頁一兩行，不是整段。要把行距補齊得把 `.prose` 的 `line-height`
從 1.85 拉到 2.3 —— 那是整站變鬆，代價大得多。

位置不用寫：Safari 對中文算出來就是 `under`（日文才是 `over`）。
顏色也不用寫，`currentColor` 是對的 —— 換顏色就多一組 PAIRS 要維護。

### F　影片外框　✅ 2026-09-11 做了

**問題**：350 × 600 的空漸層 ＋ 一個很淡的狐狸。深淺兩套都是最弱的一塊。

**做法**：把那首詩的首句直排放進去當背景，播放鍵做成印章的形狀
（`--c-seal-face`／`--c-seal-char` 兩個 token 已經有了，而 `--c-seal` 現在只用 1 次）。
仍然零請求。

**代價**：`VideoFacade` 既有的 `<style>`，0 雜湊。
**風險**：播放鍵是**可操作元件**，形狀改了要重跑 `check:a11y`
（觸控目標大小、focus 外框）。

#### 做出來是這樣

**播放鍵沒有動**（可操作元件，形狀改了風險大於收穫）。動的是它後面那張
自己畫的封面：直版的框是 280 × 498 —— 那本來就是**條幅**的比例。

- 題一句詩進去：詩的**首句**，直排、淡墨（`opacity: 0.14`）、44px
- 位置在**右上**，落款「狐」在**左下** —— 條幅就是這樣擺的（直排從右邊起頭）
- 「狐」從 96px 收到 28px：它現在是落款，不是主角

位置改過一次：第一版把題字置中，截圖上那顆播放鍵正好橫過「前」與「月」之間。
挪到右上之後量到只剩 5px 的重疊（而且是在一個有底色的鈕後面）。

那個題字是直排，所以照 `vertical-keep-all` 的要求寫出了 `word-break: normal`
—— 不寫的話它會繼承全站的 `keep-all`，而 WebKit 在直排底下對 `keep-all`
不產生斷點，整句會漏到框外面。

### G　跨頁轉場：標題接著飛過去

**做法**：列表的項目標題與詩頁的 h1 用同一個 `view-transition-name`，
點進去時標題原地長大。`view-transition-class` 已確認可用，
而逐項的名字可以走 `style="…"` 屬性 —— CSP 的 `style-src-attr 'unsafe-inline'` 允許，**零雜湊**。

**代價**：HTML 每列約 ＋40 B。
**風險**：名字必須全頁唯一；Chrome 與 Safari 的跨文件轉場行為要各看一次。
這一項**看不到就等於沒做**，所以要有截圖才算數。

### H　空下來的地方給入口

`/archive` 下半頁全空、`/elsewhere` 的「依平臺」旁邊 900px 全空。
`ARCHITECTURE.md` 已經有「空的地方要給入口，不要給空白」這條 ——
這兩處是它還沒走到的地方。

## 五、不建議做的

- **標點擠壓、標點懸掛、`text-box-trim`** —— 第三節量過，Safari 上都沒有效果。
- **任何需要 JS 的互動** —— 只剩 100 B。
- **超過 5 個新元件 `<style>`** —— CSP 雜湊會超標，而那條預算是全站共用的。
- **加陰影、玻璃、漸層堆疊** —— 跟「紙」的調性相反，而且站上有一條關卡
  在守「不要有半透明表面」（會讓算出來的對比度跟畫出來的不一樣）。
- **換字型** —— 零第三方請求是硬性限制。

（19 頁 × 12 種寬度 ＝ 228 格）可以直接重跑，量斷行、溢出、幾何；
截圖用同一支工具在深淺兩套下各拍一張。
改完照例 `verify:all` 六道 ＋ `test:tools` 44 步。

## 七、這份研究本身的限制

- 量的是 **Safari 26.6.2 的 WebKit**。Chrome 的行為要另外量 ——
  上一輪已經證明兩者在斷行上差很多。
- 沒有量**觸控裝置**：hover、游標、`:focus-within` 在手機上的行為
  這個環境測不到（瀏覽器窗格回報自己是 `pointer: coarse`）。
- 沒有量**真的載入速度**，只有位元組。
- 「好不好看」不是量出來的 —— 上面每一項都說得出**為什麼**
  （哪個數字、哪本書上的哪個東西），但最後要不要這樣做是站主的決定。
