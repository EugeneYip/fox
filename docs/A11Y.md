# 無障礙：自動守住的，與只能靠人的

`npm run check:a11y` 有 28 條規則、掃 44 頁。它跑完會說一句
「還是要人工的：⋯⋯」，然後點名三件事。

**這一份寫的就是那三件事怎麼做。** 在這之前它們只有結論沒有方法 ——
第 1 輪（第二十七圈）為了重現一個舊數字試了三種解讀才對上。

---

## 為什麼有些事自動不了

`check:a11y` 掃的是 HTML 字串。「這個按鈕在畫面上多大」「它離隔壁多遠」
「Tab 走到這裡會不會突然跳回上面」——這些要有排版引擎才算得出來，
也就是一個真的瀏覽器。這個專案**刻意沒有那個相依套件** ——
那個決定的理由與有效期限寫在
[ARCHITECTURE.md 的「檢查用的瀏覽器」](ARCHITECTURE.md#檢查用的瀏覽器這個決定的有效期限)
（第 1 輪〔第二十八圈〕重新查過：兩個理由過期了一個，結論還是不加）。

所以量法做成一段**貼上去就能跑**的程式：[`scripts/probe-a11y-layout.js`](../scripts/probe-a11y-layout.js)。
沒有相依套件、不需要安裝，任何人打開 devtools 都能重跑。

---

## 一、目標尺寸（WCAG 2.5.8）與 Tab 順序（WCAG 2.4.3）

這兩件事同一支探針一起量。

### 怎麼跑

1. `npm run dev`，或直接開 <https://bellafoxy.com>
2. devtools → 裝置模擬 → 寬度設成 **375**
3. 把 `scripts/probe-a11y-layout.js` 整個貼進 console，Enter
4. 每一頁各跑一次

### 「餘裕」是相對於 24 說的

WCAG 2.5.8 要求互動目標至少 24×24 CSS px，但有一個**間距例外**：
小於 24×24 也可以，只要在每個目標的外框中心放一個**直徑 24 的圓**、
圓與圓不相交 —— 也就是圓心距 ≥ 24。

所以探針印的**餘裕 ＝ 圓心距 − 24**。不是圓心距本身，也不是兩個框的間隙。

> 這一句是這份文件存在的主要理由。舊紀錄只寫「最小餘裕 17.9px」，
> 沒說相對於什麼。重現的時候：原始圓心距是 41.9、兩個框的間隙是 16.0、
> 圓心距減 24 才是 17.9。**三個都像答案，只有一個是。**

### 這條為什麼不寫成規則

一條只比 24×24 的規則，會在一個**完全合格**的站上報一堆假警報 ——
下面量到 36 個小於 24×24 的目標，真正違規的 0 個，全部靠間距過關。
要做對就得算圓的相交，而那需要瀏覽器。

### 基準（2026-09-04 量於 https://bellafoxy.com，視窗寬 375px）

| 頁 | 可聚焦 | 小於 24×24 | 真的違規 | 最小餘裕 | 視覺上往回跳 |
|---|---|---|---|---|---|
| `/` | 45 | 8 | **0** | 17.9px | 1 |
| `/poems/jing-ye-si/` | 20 | 6 | **0** | 17.9px | 1 |
| `/poems/` | 30 | 6 | **0** | 17.9px | 1 |
| `/about/` | 18 | 8 | **0** | 17.9px | 1 |
| `/elsewhere/` | 27 | 8 | **0** | 17.9px | 1 |

最小餘裕都出現在同一對：頁尾的**「搜尋」與「RSS」**（各約 26×18.5）。
它們是全站最擠的一對，動頁尾的間距要回來重量這一格。

正值 `tabindex`：**0 個**（所以 Tab 順序就是 DOM 順序）。
`check:a11y` 的 `positive-tabindex` 也在守這一條。

> 更早的紀錄寫「小於 24×24 的目標 28 個」，現在量到 36 個。
> 對不上的原因不明 —— 可能是這 20 圈裡站長大了、也可能是當初的選取器不一樣，
> **因為當初沒有記量法，沒辦法判斷**。從這一份開始，選取器寫在探針裡。

### 那一處「往回跳」不是違規

窄螢幕下頁首折成兩行：第一行是站名＋語言＋主題，第二行是導覽列。
Tab 走完第二行的「關於」才回到第一行右側的「語言」，視覺上往回跳一次。

2.4.3 要的是「順序保住意義與可操作性」，不是「由上到下」。
這裡的順序是**內容導覽 → 站臺工具**，語意連貫，所以不算違規。
探針只報位置，判斷留給人 —— 但如果哪天往回跳變成 2 處以上，
或者跳的是內容區而不是頁首，那就要看了。

## 二、螢幕閱讀器

### 現況：**沒有人做過**

`VoiceOver` 這個字在 repo 裡出現很多次，**沒有一次是「做了、結果是什麼」** ——
全部都是在說「還沒做」。要自己數一次：

```
git grep -o VoiceOver | wc -l
```

**這裡刻意不寫那個數字。** 原本寫的是「出現 15 次，全部在 `REVIEW-LOG.md`
裡面」，兩半都過期了：紀錄一輪一輪長，而這一份文件本身就是第二個地方。
第 1 輪（第三十三圈）想改成正確的數字，改完一數 —— 又多一次，
因為上面那行指令裡就有這個字。這一輪的紀錄寫進 `REVIEW-LOG.md` 之後還會再多。

**這是一個寫下來就會把自己弄錯的數字**，所以留指令、不留答案。
不會過期的是那半句：沒有一次是「做了、結果是什麼」。

唯一被結掉的螢幕閱讀器問題（詩詞頁直排的朗讀順序）是**不用 VoiceOver
結掉的** —— 第 1 輪（第十四圈）發現螢幕閱讀器照 DOM 順序讀，
所以只要證明「DOM 順序 == 視覺順序」就夠了，用 `getBoundingClientRect()`
逐句取 x 座標比對，烏衣巷 4 句、琵琶行 3 節 10 句都相符。
**那條待辦被原封不動帶了 8 輪才有人想到這一招。**

### 怎麼做（macOS 內建的 VoiceOver，不用裝東西）

| 動作 | 按鍵 |
|---|---|
| 開／關 VoiceOver | `⌘F5` |
| VO 鍵（下面都用這個代稱） | `Control` ＋ `Option` |
| 從頭讀下去 | `VO` ＋ `A` |
| 停 | `Control` |
| 下一項／上一項 | `VO` ＋ `→` ／ `←` |
| 開轉子（標題、連結、地標的清單） | `VO` ＋ `U`，左右鍵換類別 |

第一次開會跳教學，可以直接跳過。**音量調小一點**，它講很快。

### 這個站要聽的四件事

1. **地標清單**（`VO` ＋ `U` 選 Landmarks）——
   兩個 `nav` 不能同名。第 1 輪（第十四圈）修過一次：
   上下篇導覽本來跟主選單都叫「選單」。
2. **主題切換鈕** —— 要唸出「切到哪了」，不是只有「按鈕，已按下」。
3. **語言切換** —— `<details>` 關著的時候裡面的連結**不該被唸到**。
   （這件事探針也驗得到：關著的 `<details>` 子元素 `checkVisibility()` 是 `false`。）
4. **英文頁** —— `/en/` 底下不該有中文被英文語音唸出來。
   `check:a11y` 的 `lang-content-mismatch` 已經在擋，聽是複驗。

聽完不管有沒有發現問題，都寫進 `REVIEW-LOG.md` 那一輪的紀錄 ——
**「聽過了，沒問題」跟「沒人聽過」是兩件完全不同的事**，
而現在這一份文件之所以要寫「沒有人做過」，就是因為那兩件事在紀錄裡長得一樣。

## 自動守住的部分

`npm run check:a11y -- --list-rules` 會列出全部 28 條。
`npm run check:a11y -- --verbose` 會印出**每一條這次實際判斷過幾個元素** ——
一條只看過 2 個元素的規則，跟看過 899 個的，綠燈的意思不一樣。

跑完還會列出「這次沒有東西可看的規則」（目前 3 條：
`aria-ref`、`img-alt`、`positive-tabindex`）。
那不是「檢查過而且沒問題」，是「站上沒有這種元素」。

焦點框本身是自動守住的：`focus-outline-removed` 這條規則，
加上 `check:contrast` 會算焦點色在深淺兩套配色下的對比。
