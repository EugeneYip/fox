## 先確認專案是健康的

```bash
npm install    # 第一次
npm run verify:all
```

這一個指令會依序跑：型別檢查 → 隱私稽核 → 對比度 → 建置 → 無障礙 → 效能預算。
**六道全過才算健康。** 任何一道紅燈就先修那個，不要往下做新東西。

工具本身還有一組測試，不算在六道裡但 CI 會跑（部署前也會）：

```bash
npm run test:tools    # 全部 44 步，零網路請求
npm run test:units    # 不需要 dist 的那 40 步
npm run test:built    # 需要 dist 的那 4 步（要先 build）
```

想知道「內容變多會不會壞」的話：

```bash
npm run fixtures -- 500 --videos 400  # 灌 500 篇假內容 + 400 支假影片
npm run build && npm run check:perf # 量
npm run fixtures -- --clean         # 一定要清乾淨
```

`--clean` 會自己確認零殘留，有殘留會直接失敗。

跑不起來的話檢查 Node 版本。`package.json` 的 `engines` 要求 `>=22.19.0`
（那是相依套件 undici 的實際需求），`.nvmrc` 寫的是主版本線 `22`。

## git 歷史：已經壓成一個乾淨的 commit（2026-09-04）

**做過了。** 原本的問題是：早期的 `scripts/audit-privacy.mjs` 把四條身分規則的
真值寫死在正則裡（`pattern: /她的本名/g`），而那個檔案自己在 ALLOWLIST 裡 ——
唯一含有個資的檔案剛好豁免於自己的檢查。第 5 輪（第二圈）修好了**程式**
（值改從 gitignore 的 `identity.local.ts` 或 `PRIVACY_NEEDLES` 取得），
**但已經進到 git 歷史的東西，改程式救不回來。**

2026-09-04 把 213 個 commit 壓成一個。選這個做法的理由：

- **不需要知道那些值就一定清得乾淨** —— 針對性重寫（`git filter-repo`）要先
  列舉出每一個字串，而這台機器上沒有 `identity.local.ts`，`check:history`
  跑不了（它會誠實地說「什麼都沒有檢查」並 exit 1）
- **連 commit message 一起清掉** —— 第三圈第 5 輪記過「commit message 裡的
  個資，檢查工具看不到」
- **輪次紀錄不靠 commit 歷史保存**，它在 `docs/REVIEW-LOG.md` 這個檔案裡

代價：失去 213 筆的 `git blame`／`bisect`。

### 還沒做完的最後一步

壓完之後，舊的 commit 物件**還在 `.git` 裡**（reflog 指得到），只是不再被
任何分支指到。正常的 `git push` 只會送出「指得到的」物件，所以推上去不會帶著它們。
但要真的從這台機器上刪掉，還要跑：

```bash
git reflog expire --expire=now --all && git gc --prune=now
```

**跑完就救不回來了**，所以留給你自己決定什麼時候跑。
（在那之前，如果發現壓錯了，`git reflog` 找得回舊的 HEAD。）

### 推之前的最後確認

```bash
npm run check:history                  # 需要 identity.local.ts 或 PRIVACY_NEEDLES 才跑得動
git ls-files -- src/config/identity.local.ts   # 要沒有輸出
                                              # （identity.local.example.ts 是刻意公開的範本，不算）
npm run verify:all && npm run test:tools
```

`check:history` 查**三個地方**：檔案內容（`git log -S`）、commit message、
以及 tag／branch 的名字。`-S` 看不到只寫在訊息或 ref 名字裡的字串，
第 5 輪（第三、四圈）實測確認過。沒有值可搜尋時它會 exit 1 並說
「什麼都沒有檢查」，不會給假的綠燈。

（那支腳本刻意不叫你自己下 `git log -S"名字"` —— 那會把本名留在 shell 的
歷史紀錄裡，為了查個資外洩而製造另一份個資。）

**推之前一定要先 rebase。** 排程的 `sync-feeds` 每天自己 commit 兩次
`src/data/syndication.json`，所以本機幾乎一定落後：

```bash
git pull --rebase origin main && git push
```

撞到的一定是 `syndication.json`（兩邊只差時間戳）。它是
`scripts/sync-feeds.mjs` 產生的，取遠端那一份：

```bash
git checkout --theirs src/data/syndication.json && git add src/data/syndication.json && git rebase --continue
```

推完立刻確認個資檔沒被帶上去：

```bash
git ls-files | grep -c identity.local    # 必須是 0
```

它描述的那件事今天還是真的嗎？**
理由：第四十四圈第 4 輪那條（「`rss` 兩條路沒跑過」）花五分鐘就結掉了，
而它被原封不動抄了十幾圈；第 2 輪那條（「要重量得先推」）在推的權限下放那天
就失效了，而它照樣被抄。**待辦清單是靠複製貼上延續的，沒有人回頭驗過。**
那份清單現在兩百多條、十六條掛著「→ 站主」。

（第四十四圈問的是：這件事，站主要自己做嗎？
八輪問了八條，而**純粹是他的決定只有一條**。那個標籤實際上蓋住三種東西：
真的要他決定、有人做得到只是沒人做、以及誰都做不了。
而被擋住的往往不是決定本身，是**決定所需要的那個事實** ——
第 6、7、8 輪的改法都不是替他決定，是把那個事實補上。）

（第四十三圈問的是：這個綠勾的分母是什麼？誰決定了它？
八輪八個分母，**沒有一個是算錯的** —— 錯的一律是它涵蓋的範圍，
而範圍由一份人挑的東西決定。那些東西只有三種：**副檔名清單**、
**路徑／資料夾清單**、**屬性／樣式清單**，而八輪裡有五輪的兇手是
「清單裡少了一個今天真的存在的名字」。
最貴的一條：**那句用來說明涵蓋範圍的話，自己也有涵蓋範圍** ——
`check:a11y` 有一句專講「我掃不到什麼」，而它只認 `<a href=`。
八輪的修法都一樣：能推導的改成推導，推導不出來的就把「我沒看哪些」印出來。）

（第四十二圈問的是：這份清單是誰維護的？漏一個會怎樣？
八輪八份清單**今天全部是對的**，缺的一律是守它的東西。清單有三種，
風險差很多：**註冊表**漏一項 → 那個東西根本不存在（沒註冊的內容資料夾，
建置成功、頁數沒變、離開碼 0）；**補 0 名單**漏一項 → 規則從計數消失；
**語料定義**漏一項 → 檢查悄悄變窄，**而輸出照樣說 ✓** —— 第三種最安靜。
另外有兩份「清單」不長得像清單：一段註解，與五份翻譯用的對照表。）

（第四十圈問的是：這段東西，站上真的跑過嗎？
「沒跑過」有三種，風險差很多：沒有語料（低，關卡自己會說）、
沒有內容（中，第一次有內容那天會一次全撞上）、
**只在測試裡跑過（高）** —— `check:perf` 那句改法叫人去改一個
早就不存在的 prop，而唯一跑過它的測試斷言的正是那個過期的字。
另一半的價值在「確認沒事」：三條閒置 a11y 規則第一次碰到主體是對的、
整條同意路徑第一次被走過是對的、兩個 CI 假設都已經有人守。）

（第三十九圈問的是：這條待辦還活著嗎？
假設是「清單裡塞了一堆已經解決的東西」，**假設錯了** ——
驗了約四十條，真正不成立的只有兩條半。真正的問題是**數字會漂**
（11→13、5→7、3.4×→3.6×），而且四次撞到「待辦記的只是問題的一角」。）
第三十八圈結束時，「待辦」那份清單有**九十幾條**，而它是**只進不出**的：
每一輪往上加，很少有人回頭確認舊的還算不算數。而那一圈就撞到兩條已經不成立的
（`related` 站上今天 0 筆；「偶發紅燈沒有留下證據」追下去是結構性的、當場修掉了）。
一份沒有人回頭驗的清單會慢慢變成噪音 —— 真的重要的那幾條會被埋掉。
判準：**拿今天的 repo 驗一次 —— 還成立嗎？還是已經被別的改動解決了？**
還成立的留著並補上今天的數字，不成立的**寫明為什麼**再刪掉。

（第三十二圈問的是：第一版做對了嗎？
八輪裡**沒有一次是「判斷寫錯了」** —— 壞掉的全在旁邊：
範圍、分母、統計、以及沒有語料踩得到的那些邊界。）

（第三十一圈問的是：是我們選的，還是它剛好長成這樣？
八輪八個，**沒有一個是「有人選錯了」** —— 最難發現的一種錯是「剛好相等」。）

（第三十圈問的是：如果現在整個拿掉，會有誰發現？
八輪問八次，**七次的答案是「沒有人」** —— 而多數不是因為東西沒用，
是因為沒有人在看。）

（第二十九圈問的是：第一次做的人跟第一百次做的人，看到的是同一份東西嗎？
不是「輸出太長」，是**同一行字對兩種人講的不是同一件事**。）

（第二十八圈問的是：這件事，是誰決定的？那個人還在嗎？
不是「為什麼這樣做」，是**那個決定的有效期限**。）

（第二十七圈問的是：這件事，換一個人來做，做得到嗎？
第一次 clone 下來要跑什麼、缺哪個檔案會發生什麼、錯誤訊息看不看得懂、
`identity.local.ts` 這種「只有站主有」的東西擋住了哪些路、
以及她要發一篇文時，從第一步到看到它上線，說明夠不夠她一個人走完。）

### 最近一圈（第三十八圈：這件事現在靠誰記得）

八輪找到的東西分成三種形狀。

**一、只有描述，沒有人提醒**（第 1、2、8 輪）：記得把探針貼進 console、
記得回來跑 `probe:served`、記得**怎麼寫**那段量測程式。
第 8 輪最細 —— 留下來的是一句描述，而照著它重寫的人要自己決定選取器與走法，
**那正是會出錯的地方**。

**二、警報在它最需要的那一刻走不到**（第 4 輪）：來源全部失敗 → 資料沒變 →
不部署 → `check:content` 不跑 → 「來源已經 N 天沒成功」那個鬧鐘**不會響**。

**三、綠燈與結尾在說謊**（第 5、7 輪）：沒有 `identity.local.ts` 時
身分規則不跑而結尾照樣寫「乾淨」（**而這個 repo 是公開的**）；
`test:tools` 紅的時候輸出結尾是 85 行 `✓`。
後者順帶解釋了第三十七圈的懸案 —— 那兩次我看的是結尾。

**一半的輪次量出來是 0 個問題**（25 個數字沒變、94 個指令沒壞、
覆蓋率 100%、8 種組合都在表上）——
**這一圈的價值不在抓錯，在讓「忘記」變成看得見的。**

完整紀錄在 [REVIEW-LOG.md](REVIEW-LOG.md) 的「第三十八圈走完了」。

## 接手時最容易踩到的坑

這些在 [CLAUDE.md](../CLAUDE.md) 有完整清單，這裡挑三個最貴的：

1. **repo 是公開的。** 本名、學歷、email 只能放在 `src/config/identity.local.ts`
   （已 gitignore）。`privacy.ts` 裡只有開關，沒有值。取值一律走 `reveal()`。
2. **`astro.config.mjs` 的 `base` 必須是 `/`。** repo 叫 `fox` 但綁了自訂網域，
   網站在網域根目錄。改成 `/fox` 會讓所有樣式和連結壞掉。
3. **`public/CNAME` 不能刪。** 少了它 GitHub 會默默取消自訂網域。
   `deploy.yml` 有一道檢查擋這個。
