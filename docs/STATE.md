## git 歷史：已經壓成一個乾淨的 commit（2026-09-04）

**做過了。** 原本的問題是：早期的 `scripts/audit-privacy.mjs` 把四條身分規則的
真值寫死在正則裡（`pattern: /她的本名/g`），而那個檔案自己在 ALLOWLIST 裡 ——
唯一含有個資的檔案剛好豁免於自己的檢查。第 5 輪（第二圈）修好了**程式**
（值改從 gitignore 的 `identity.local.ts` 或 `PRIVACY_NEEDLES` 取得），
**但已經進到 git 歷史的東西，改程式救不回來。**

2026-09-04 把 213 個 commit 壓成一個。選這個做法的理由：

- **不需要知道那些值就一定清得乾淨** —— 針對性重寫（`git filter-repo`）要先
  列舉出每一個字串，而這台機器上沒有 `identity.local.ts`，`check:history`
  跑不了（它會誠實地說「什麼都沒有檢查」並 exit 1）
- **連 commit message 一起清掉** —— 第三圈第 5 輪記過「commit message 裡的
  個資，檢查工具看不到」
- **輪次紀錄不靠 commit 歷史保存**，它在 `docs/REVIEW-LOG.md` 這個檔案裡

代價：失去 213 筆的 `git blame`／`bisect`。

### 還沒做完的最後一步

壓完之後，舊的 commit 物件**還在 `.git` 裡**（reflog 指得到），只是不再被
任何分支指到。正常的 `git push` 只會送出「指得到的」物件，所以推上去不會帶著它們。
但要真的從這台機器上刪掉，還要跑：

```bash
git reflog expire --expire=now --all && git gc --prune=now
```

**跑完就救不回來了**，所以留給你自己決定什麼時候跑。
（在那之前，如果發現壓錯了，`git reflog` 找得回舊的 HEAD。）

### 推之前的最後確認

```bash
npm run check:history                  # 需要 identity.local.ts 或 PRIVACY_NEEDLES 才跑得動
git ls-files -- src/config/identity.local.ts   # 要沒有輸出
                                              # （identity.local.example.ts 是刻意公開的範本，不算）
npm run verify:all && npm run test:tools
```

`check:history` 查**三個地方**：檔案內容（`git log -S`）、commit message、
以及 tag／branch 的名字。`-S` 看不到只寫在訊息或 ref 名字裡的字串，
第 5 輪（第三、四圈）實測確認過。沒有值可搜尋時它會 exit 1 並說
「什麼都沒有檢查」，不會給假的綠燈。

（那支腳本刻意不叫你自己下 `git log -S"名字"` —— 那會把本名留在 shell 的
歷史紀錄裡，為了查個資外洩而製造另一份個資。）

> 自己跑了 48 個突變、第一次漏 6 個，而六次漏掉的原因每一次都是同一個主題：
> 案例的形狀太窄。（其中兩次追下去發現是死碼、以及「放寬反而比較對」。）

> **第十二圈只做一件事：用不是預設的方式走一次。**
> 前四圈走的都是主路（JS 有跑、儲存能用、字型有裝、關卡全綠）。
> 這一圈每一輪問同一個問題，只換一個人來問：**不是預設的那條路上，
> 站在那裡的人看到什麼？** 使用者、作者、操作者、維護者、讀詩的人。
> 八輪找到 **3 個使用者現在就碰得到的缺陷**（被念出來的置頂星號、
> 沒有 JS 時兩個死掉的按鈕、橫放手機上折斷的七言）
> 與 **3 個「別人」碰得到的**（作者看到的錯誤訊息、操作者看不懂的三則訊息、
> 維護者拿不到的失敗原因）。最一致的一件事：**那條路上沒有人走過，
> 所以那裡的東西從來沒有被檢查過** —— `prefers-reduced-motion` 列在輪替表裡
> 十一圈沒量過、`ci:sim` 的失敗分支十二圈沒跑過、八則同步訊息只有兩則被看過。
> 自己犯了四次錯，全部是「探針沒有分辨力」或「模擬跟真的不一樣」，
> 而抓到的方法有一半是**換一種原理再量一次**。

> **第十一圈只做一件事：拿真正跑起來的結果當對照組。**
> 前三圈都在看工具（會不會紅、紅得對不對、看不看得到）；這一圈改成
> 打開瀏覽器、打開網路、把東西真的跑一次，再拿那個結果去對每一份文件、
> 每一條規則、每一個假設。八輪找到 **5 個使用者現在就碰得到的缺陷**
> （被念出來的裝飾箭頭、印給讀者看的內部代號、到不了畫面的錯誤訊息、
> 指向 404 的語言鈕、以及 19 頁的 `hreflang`）。
> 最一致的一件事：**每一個發現都落在「兩個各自正確的東西之間」** ——
> 所以先讀程式碼猜哪裡會錯是找不到的，分開看每一段都對。
> 自己也犯了六次錯，全部是「用簡化的模型代替真正的東西」，
> 而抓到的方法有一半是**兩個量測互相矛盾**。

> **第十圈只做一件事：問「這個工具結構上看不見什麼」。**
> 第八圈看工具做了什麼，第九圈看它證明了什麼；第十圈往外一層，
> 看它**沒有在看什麼**。答案八輪都一樣：一份手寫的清單、一個手動的步驟、
> 一個沒有人驗證的邊界。八輪找到 **4 個使用者現在就看得到的缺陷**
> （手機上 9／9 的影片標題被切掉一半、詩的方向跳 434px、8 處雙層書名號、
> 指向自己的連結）與 **4 個「以後不會有徵兆」的缺口**。
> 跟前兩圈不同的是：**這一圈有一半修的是網站本身** ——
> 因為看不見的地方，正是缺陷活得最久的地方。
> 七輪都有自己犯的錯，全部在寫進紀錄前被抓到；其中一次是靠**上一圈留下的
> 數字**當對照組發現的 —— 留下數字，不要只留結論。

> **第九圈只做一件事：問「這個案例證明的，是不是它宣稱的那一條」。**
> 第八圈驗的是「該紅的時候會不會紅」；第九圈往裡面再一層 ——
> **紅的是不是它宣稱的那個原因**。六支規則測試、75 個案例，
> 量之前有 **34 個會順帶觸發別的規則**，其中只有 3 個是結構上必然的。
> 最後一輪找到同一個問題的另一面：`test-contrast` 的 fixture 是六支裡最乾淨的，
> **斷言卻是最鬆的** —— 「案例有沒有被汙染」跟「斷言有沒有問對問題」
> 是兩件獨立的事。這一圈我自己犯了五次錯，全部在量測工具而不是網站上，
> 五次都在寫進紀錄前被自己抓到 —— 因為每一次都再量一次。

> **第八圈只做一件事：問「這個東西證明的，是不是它宣稱的東西」。**
> 方法是系統性突變掃描 —— 把被守的程式碼一處一處改壞，看測試會不會紅、
> 紅得具不具名。八輪找到 **8 個靜靜通過的突變、2 個誤報地雷、2 個借錯的字串**。
> 最重的是第 5 輪：稽核最重要的那條規則與豁免清單的互動**一條測試都沒有**，
> 而那正是第二圈找到並修好的 bug。
> 這一圈我自己也犯了四次錯，全部在量測工具而不是網站上，
> 四次都在寫進紀錄前被自己抓到 —— 因為每一次都再量一次。

> **第七圈的主題是「先問現有的東西守不守得住，再決定要不要動」。**
> 八輪裡有四輪的結論是「不做」，而每一個「不做」都帶著數字 ——
> 28 個假警報、1.8 秒換一個已知的失效模式、規約的原文範圍。
> 這跟「沒空做」不一樣：那些是可以被推翻的理由，不是藉口。
> 這一圈我的探測寫壞了四次，四次都在寫進紀錄前被自己抓到（因為每次都再量一次）；
> 另有一個文案違規 commit 進去，隔一輪被 `ci:sim` 抓到 ——
> 修法不是「下次小心」，是改掉教錯的文件。

> **第六圈只做一件事：找出「從來沒有真的被執行過」的東西。**
> 八輪全部找到，形狀一致 —— 每一個都是「這段程式碼存在、看起來合理、
> 而且從來沒有跑過一次」。其中三個是**檢查本身**沒被執行過；
> 一個沒有跑過的檢查，跟沒有那個檢查是一樣的。
> 這一圈也自己製造了兩個錯誤（第 3 輪的錯誤宣稱、第 8 輪第一版的 grid），
> 兩個都是量測抓到的，不是靠回想。

> **第五圈只做一件事：問每一個結論「它是在什麼條件下量出來的」。**
> 八輪全部找到東西，而且全部是同一個形狀 —— 結論本身沒錯，
> 錯在它被當成無條件成立。其中三次的條件是「剛好沒事」
> （規則永遠不響、0 個例外、A4 直式）。**沒事不等於對，
> 而分辨這兩者唯一的方法是把條件寫下來。**

> **第四圈只做一件事：把「檢查本身是不是真的在檢查」做完。**
> 八輪裡有五輪找到的是「該擋卻不會擋」或「該跑卻跑不起來」——
> 其中兩個是這一圈自己製造的。現在六道關卡與所有工具檢查
> **每一條都有「會響」的案例**，加規則沒加案例測試會直接失敗。

> **第三圈的共同主題是「檢查本身是不是真的在檢查」。** 八輪裡有五輪的
> 主要發現屬於同一類：一個看起來在運作的東西，其實量錯了、沒守住、
> 或根本沒生效。「有一個檢查」跟「那個檢查會在該響的時候響」是兩件事。

> **第二圈的性質跟第一圈不一樣。** 第一圈補的是「完全沒有」的東西；
> 這一圈找到的多半是上一圈修過又壞掉、或者**我自己在這一圈弄壞的**
> —— 第 6、7、8 輪的主要發現都有這一圈自己製造的成分。
> 這正是輪替式檢查的價值：改動會製造新的表面，下一輪會回頭看它。

**工具上的兩個坑（第 8 輪踩到，記著免得重蹈）：**

- CSP 的 `frame-src` 會擋掉**同源** iframe，所以任何靠 iframe 的量測工具都不能用。
  不要為此放寬 CSP —— 改用真實導覽逐頁量
- 截圖在窄視窗、或剛改完狀態時不一定重繪。**看起來壞掉時先用
  `getComputedStyle` 或 `get_page_text` 確認**，再決定要不要修。
  第 8 輪被這個假象騙了兩次，差點去修不存在的 bug

**不屬於任何輪次、要站主自己做的：**

- **⚠ `PRIVACY_NEEDLES` secret 現在是部署的必要條件。**第 5 輪（第七圈）把「沒有 needles」在 CI 上從綠燈改成紅燈 ——第一次 push 之後 CI 會擋住、不會部署，直到那個 secret 設好。那本來就是部署步驟的第 1 步，現在從「記得要做」變成「不做就不會上線」。理由：repo 是公開的，而一個什麼都沒檢查的綠燈比紅燈危險。

### 怎麼重新啟動這個 loop

在 Claude Code 裡貼這一段（內容跟 REVIEW-LOG.md 的規則一致，
所以就算這段文字掉了，照 REVIEW-LOG.md 做也是一樣的）：

```
/loop 讀 docs/REVIEW-LOG.md，找到「紀錄」區最後一筆結尾的「下一輪：N — 面向」，
就做那一輪。做完把該輪的紀錄依既有格式 append 到檔案末尾，並在結尾寫下一輪的
編號與面向（走完第 8 輪回到第 1 輪）。

規則：只做這一輪的面向，順手看到的別的問題記進該輪的「待辦」不要當場擴散；
要實際量測不要憑感覺；改完 npm run verify:all 要全過；沒發現問題就誠實寫
「沒發現」，不要為了有東西交而製造改動；不要 push。

專案限制：不加日文，只有 zh-TW 與 en；零第三方請求；個資不得進 repo，
取值一律走 reveal()；除了 YouTube 其他平臺帳號都還不知道，不要編造帳號。
```

不想用 loop 也完全沒問題 —— 那些檢查都是普通的 npm script，手動跑一樣。

## 接手時最容易踩到的坑

這些在 [CLAUDE.md](../CLAUDE.md) 有完整清單，這裡挑三個最貴的：

1. **repo 是公開的。** 本名、學歷、email 只能放在 `src/config/identity.local.ts`
   （已 gitignore）。`privacy.ts` 裡只有開關，沒有值。取值一律走 `reveal()`。

   網站在網域根目錄。改成 `/fox` 會讓所有樣式和連結壞掉。

   `deploy.yml` 有一道檢查擋這個。
