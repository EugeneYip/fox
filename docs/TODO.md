## 卡住最久、而且價值最高的三件（都需要站主）

- **她自己發文那條路沒有走完過。** `npm run write` 產出 markdown，
  但從那裡到「站上看得到」中間她要自己 `git` 三次。
- **英文那一半沒有人系統地讀過。** `check:copy` 守的是寫法（全形標點、空格），
  不守「讀起來對不對」。
- **螢幕閱讀器從來沒有人測過**（`docs/A11Y.md` 自己寫著「現況：沒有人做過」）。

- **內容 frontmatter 的 `platform` 沒有人在驗，而 `sources.mjs` 的有。**
  `external` 的 `platform` 與 `posts` 的 `alsoOn[].platform` 都是 `z.string()`，
  而同一份 schema 裡的 `related` 用的是 Astro 的 `reference()` —— 這個 repo
  知道怎麼宣告真的參照。第 3 輪（第五十二圈）實測打錯一個字的後果：
  建置離開碼 0、`/elsewhere` 多一格灰色的假平臺、多產生兩頁、進 sitemap／
  rss-all／search-index／首頁／`/about`，**七道關卡一道都沒說話**
  （唯一紅的是 `unlabelled-cjk`，而它抓的是另一件事）。
  `sources.mjs` 那一半由 `verify-sources`／`sync-health --strict` 守著。
  沒有當場加檢查是因為「過去十輪沒有真的事故」那一條 —— 站上手動登錄目前 0 筆。
  真的要補的話最省的地方是 schema（`content.config.ts` 可以 import
  `platforms.data.mjs`，那個拆分本來就是為了讓沒有編譯步驟的東西讀得到）。
- **手動登錄外站文章那條路整個沒有算繪過。** 站上 `external` 集合 0 筆
  （唯一那份是 `draft: true` 的範本），所以 `SyndicationList` 的 `why` 那一行、
  `/elsewhere/<平臺>/` 對應手動平臺的那種頁、以及 `platformOrFallback` 的
  灰色樣式都從來沒有跟真資料跑過。第 3 輪（第五十二圈）把它暫時打開量了一次，
  當場抓到 `why` 少標 `lang`（已修）。

- **`confidence` 這個欄位名裝的是兩種不同的東西。** 型別說明寫著
  「這個 pattern 我實際打過嗎？」，而三個值裡 `verified`／`documented`
  是可信度、`lookup-required` 是**方法**（「要到該平臺頁面上找 RSS 圖示」）；
  而「這個 pattern」對 24 個平臺裡的 12 個根本不存在（`--patterns` 印「無樣板」）。
  `docs/PLATFORMS.md` 顯示給人看的中文標籤（已實測／依文件／需自行查）反而誠實。
  第 4 輪（第五十二圈）量到，沒有動：名字散在資料檔、型別、產生的文件與 UI 上，
  而且今天沒有任何東西因此判斷錯。

- **「CSP 雜湊數」那條預算只有上限，沒有下限。** 第 5 輪（第五十二圈）實測：
  把 `style-src` 的雜湊鎖拿掉（`styleDirective` 改成 `kind: 'element'`），
  單頁雜湊數從 36 掉到 12，那條預算從 88% 變成 **29%** —— 一個安全性的退步
  在螢幕上是一條變短的綠色長條。現在 `csp-unsafe-inline` 會擋這一種了，
  但「雜湊數突然掉一半」本身仍然沒有人看。要不要給它一個下限是另一件事。

- **`verify:all` 的「邊界」沒有人在守。** `gate-count-stale` 比的是**數目**
  （`verify:all` 有幾步 vs 四份文件寫幾道），但沒有東西比**成員** ——
  而 `CLAUDE.md` 與 `REVIEW-LOG.md` 的規則區都寫著一句負面宣稱：
  「`check:copy` 與 `check:content` 不在裡面，住在 `test:tools` 那一半」。
  哪天有人把 `check:copy` 加進 `verify:all`，數目那一條會響（6 → 7），
  而那兩句話會安靜地變成假的。沒有當場加檢查：過去十輪沒有人動過成員。

- **`aria-current` 在四個元件裡身兼無障礙狀態與樣式鉤子，而沒有一處寫下來。**

  另外三個沒動 —— 它們的值彼此一致，沒有「看起來像漏改」的誘因。

- **`sitemap-0.xml` 沒有 `lastmod`。** 第 3 輪（第五十三圈）量到：改一篇的

  它只有 `<loc>`。爬蟲因此收不到「這一頁動過了」的訊號。

- **站上唯一一個手寫的逃逸函式，沒有任何關卡在守。**（2026-09-11）

## 工具與檢查

- **沒有任何一道關卡量得到「算繪出來的幾何」。**（2026-09-11）
  第 8 輪（第五十四圈）的突變掃描量到的：把注的行距改回 `--lh-snug`、

  都撤掉），`verify:all` 六道、`test:built`、`check:content` **全部綠燈**。
  行框幾 px、頁首佔畫面幾成、詩塊捲不捲得動 —— 這些都要真的算繪才量得到，
  而七道關卡都是掃檔案的。要做的話跟 `verify` 同一類（需要跑瀏覽器），
  **先確認值不值得**：這種檢查很容易變成對著像素寫死的期望值。

- **取 YouTube 影片 ID 的寫法還有第三份。**（2026-09-11）
  詩頁與搜尋索引現在共用 `@lib/syndication` 的 `youtubeId()`，
  但 `scripts/check-content.mjs` 的 `external-date-drift` 還有自己一份 ——
  那一支是 `node` 直接跑的 `.mjs`，沒有 `--experimental-strip-types`，
  import 不了 `.ts`。要收掉的話得先決定 `check:content` 要不要跟
  `check:copy`／`make-icons` 一樣帶那個旗標

- **「script 造出來的元素配不到 scoped CSS」沒有東西在守。**（2026-09-09 的事故）
  `VideoFacade` 的 `.facade iframe` 被編譯成 `iframe[data-astro-cid-…]`，
  而那個 iframe 是按下播放時 `createElement` 出來的，身上沒有那個屬性 ——
  **整組樣式一條都沒套上**，iframe 用 HTML 預設值算繪成 304×154
  （300×150 加預設 2px 邊框），直版影片變成框裡一小條橫的。
  站主是自己按了播放才發現的；六道關卡與 `test:tools` 全綠。
  這個規矩站上本來就在用（`search.astro` 有 6 條 `:global()`），
  漏的是唯一一個從來沒被算繪過的元件。
  做得起來的話很窄：掃 `.astro` 的 `<script>` 裡 `createElement('x')`
  與 `innerHTML` 用到的 class，跟同一個檔案 `<style>` 裡沒有包 `:global()`
  的選擇器對一次。**先確認它跟現有的哪一支關卡放在一起才合理**

- **「一般頁面內嵌 JS」剩 0.1 KB 額度**（2026-09-08 量）。接上影片之後
  `poems/jing-ye-si` 是這條預算的最大值：2.9 KB／上限 3.0 KB（96%）。
  VideoFacade 那段是 561 B，**每頁一份、不會累加** —— 所以再多幾首詩接影片
  不會把它推高；但共用版面上任何一段新 JS 都會。
  真的紅燈的時候，改法是把 facade 那段從內嵌抽成獨立檔案

- **站外連結沒有東西在守**（第四十八圈第 4 輪量到）。`check:links` 只看站內
  （44 頁、1263 個）；「各處」那一頁的九個 YouTube 連結從來沒有人檢查過 ——
  影片下架就是九個死連結而沒有徵兆。這一輪手動驗過 9／9 都在。
  判準要用 oEmbed（`/oembed?url=…&format=json`）**不能用 `/watch?v=`**：
  後者對下架的影片也回 200。要做成常設檢查得打網路，跟 `verify` 同一類
- **`<main>` 沒有 `tabindex="-1"`**（第四十八圈第 1 輪量到）。鍵盤沒問題 ——
  按下跳過連結之後 `activeElement` 雖然是 `BODY`，接下來三次 Tab 都落在主要內容裡
  （瀏覽器把片段目標設成循序焦點的起點）。加上去的話焦點會真的移過去、
  各家輔助技術一致 —— 但**要有螢幕閱讀器才驗得出差別**
- **這個環境按不動原生控制項**（第四十八圈第 1 輪）：Enter／空白鍵在
